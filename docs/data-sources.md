# Data sources and publication policy

**Scope:** Generation 9 battle and Pokédex data. This living document applies the accepted [data authority decision](adr/ADR-002-data-authority-and-provenance.md) to source selection and cache behavior. It records current code behavior and limitations; it does not grant rights to third-party text or images.

## Authority by data type

| Data used by the site | Authority and current implementation | Boundary |
| --- | --- | --- |
| Type effectiveness, species names and base stats, moves, abilities, items, natures, and damage mechanics | Pinned `@smogon/calc` `0.12.0`, selected with `Generations.get(9)` in the [catalog](../apps/api/src/modules/catalog/catalog.ts) and [damage adapter](../apps/api/src/modules/damage/smogon-adapter.ts). The [calculator project](https://github.com/smogon/damage-calc/blob/master/README.md) supplies a generation-specific data layer and damage ranges. | These values are not replaced by PokéAPI fields. Dependency upgrades need catalog and representative damage regression checks. |
| Official Pokédex eligibility, National Dex number, Pokémon/form IDs, sprite stems, and evolution-chain IDs | The checked-in [identity manifest](../apps/api/src/modules/catalog/pokedex-identities.json) is generated by [a reproducible script](../apps/api/scripts/generate-pokedex-identities.mjs) from PokeAPI CSV files pinned to one repository revision and audited against the pinned Generation 9 calculator catalog. Curated aliases map catalog names and defaults to exact PokeAPI forms. | `pokedexEligible` filters only the Pokédex tab; custom and composite calculator entries remain in battle tools. National Dex numbers are distinct from Pokémon IDs, form IDs, and PokéAPI species IDs. Regenerate and review the manifest when refreshing either pinned source. |
| Official English and Spain-Spanish labels | The committed [generated translations](../apps/api/src/modules/catalog/pokemon-translations.generated.json) come from the reproducible identity/catalog generator and PokéAPI CSVs pinned to revision `2bf639e5572812a67d2b94903fdcb9d095f5aeb2`. English uses PokéAPI language 9 and Spain Spanish uses language 7; language 14 (`es-419`) is explicitly excluded. The snapshot covers species/forms, moves, abilities, items, types, and natures, with documented official-name overrides and explicit exceptions for non-official simulator entities. | These labels affect display only. Canonical calculator identifiers remain English in drafts, requests, saved teams, and validation. A missing official name must use a recorded source-backed override or an explicit exception; do not invent Pokémon terminology. Ordinary interface copy is translated in the web locale dictionaries. |
| Ability descriptions | The committed [generated descriptions](../apps/api/src/modules/catalog/ability-descriptions.generated.json) use official PokéAPI ability flavor-text rows in English (language 9) and Spain Spanish (language 7). Scarlet/Violet text is preferred; if absent, the latest available text from an earlier game group is used, and its source group is recorded. | Some abilities have no bilingual official flavor text in the pinned revision and are marked unavailable instead of receiving invented text. Descriptions are local generated data; the server does not make a separate live ability request for each entry. |
| Pokédex artwork, height, weight, and abilities | The server's [PokéAPI adapter](../apps/api/src/modules/catalog/pokeapi-adapter.ts) requests the [Pokémon endpoint](https://pokeapi.co/docs/v2#pokemon) for the manifest's exact Pokémon ID and stores ordered image URLs, measurements, ability names, and hidden status. The detail-art priority follows the [PokéAPI sprite collection](https://github.com/PokeAPI/sprites#sprites): Scarlet/Violet, Legends Z-A, Champions, HOME, then official artwork. Normal and shiny candidates are collected separately. | Descriptive only. Missing artwork or ability descriptions must leave battle features usable. The API validates artwork URLs against the sprite repository path; image bytes load from GitHub in the browser and are not cached by the server. The Pokédex advances through candidates on image errors and displays a placeholder when all fail. |
| Evolution families and Mega forms | `GET /api/pokedex/:species/evolution` reads the [PokéAPI evolution-chain endpoint](https://pokeapi.co/docs/v2#evolution-chains), maps chain species to manifest identities, and uses stored sprite stems for Scarlet/Violet PNG icons followed by official-artwork PNG fallbacks, without requesting each family member. | Evolution chains are cached by chain ID for 24 hours using the existing JSON cache table. A method's conditions are combined with AND; alternative methods are combined with OR. Scarlet/Violet methods take priority; otherwise default methods are used, falling back to all returned methods only when PokéAPI marks none as default. |
| Scarlet/Violet move learnsets | The generated [server-side learnset snapshot](../apps/api/src/modules/catalog/pokemon-moves.generated.json) is derived from pinned `pokemon_moves.csv`, `pokemon_move_methods.csv`, `machines.csv`, `moves.csv`, `move_names.csv`, and `version_groups.csv`. It selects only version group 25 (`scarlet-violet`), records source revision and unavailable entries, and includes machine numbers when provided. Move type and physical/special/status metadata come from the pinned source and the matching Generation 9 catalog. | This describes the base games only; The Teal Mask and The Indigo Disk are excluded. Missing category or type remains unavailable. Learnsets are informational and do not enforce team legality. |
| Move-category icons | Physical, special, and status artwork uses the official Scarlet/Violet game icons published by [Bulbagarden Archives](https://archives.bulbagarden.net/wiki/File:PhysicalIC_SV.png), [SpecialIC_SV.png](https://archives.bulbagarden.net/wiki/File:SpecialIC_SV.png), and [StatusIC_SV.png](https://archives.bulbagarden.net/wiki/File:StatusIC_SV.png). | PokéAPI provides the category metadata but does not publish these game icon assets. The API's Helmet image policy allows the archive origin for these icons. Availability and reuse rights remain subject to the source's terms. |
| Guest and saved teams | Entered by the user, validated against known names and field ranges. | These are user data, not evidence that a set was legal or played in an event. |

The [Smogon calculator README](https://github.com/smogon/damage-calc/blob/master/README.md#license) identifies the package's MIT license. [PokéAPI's fair-use policy](https://pokeapi.co/docs/v2#fair-use-policy) asks consumers to cache requested resources; the server caches selected response fields, while sprite image bytes remain external. The rights to Pokémon imagery are a separate matter; do not assume an open API alone grants every reuse right.

## PokéAPI mapping, cache, and failure behavior

The API accepts only species marked eligible in the checked-in [identity manifest](../apps/api/src/modules/catalog/pokedex-identities.json). The manifest is built from `pokemon.csv`, `pokemon_forms.csv`, `pokemon_species.csv`, `pokemon_dex_numbers.csv`, and `pokedexes.csv` at its recorded PokéAPI revision, then audited against all Generation 9 calculator entries. It keeps National Dex numbers, Pokémon resource IDs, form resource IDs, species resource IDs, evolution-chain IDs, exact Pokémon sprite stems, default-form metadata, and curated aliases as distinct values. The manifest generator asserts both catalog coverage and National Dex number coverage before writing, so an upstream or catalog refresh that changes coverage must be reviewed instead of silently omitting entries. Catalog entries outside that set, including custom and calculator-composite names, stay available to battle features and are filtered from the Pokédex tab only. Ogerpon's four official Tera states remain listed with their National number and an explicit unavailable-art state.

A fresh detail response uses `pokedex:v4:{canonical-name}` and a fresh family response uses `evolution:v1:{chain-id}` in the existing JSON cache, both for 24 hours. Ability text and Pokémon translations come from committed generated snapshots, not per-entry live requests. The detail adapter requests one exact Pokémon resource by its manifest ID, orders the API-provided normal and shiny image URLs by game source, and returns separate male/female normal and shiny candidates. Female candidates use exact female sprite URLs when PokéAPI supplies them and share default artwork when there is no visible gender difference; explicitly gender-specific forms expose no candidate for the unavailable gender. The adapter retains `sprite` as the first normal candidate for older consumers. A shiny or gender-specific selection has no fallback to a different variant. On fetch, status, parse, or cache failure, each route uses an older valid payload when available and marks the response `stale`; with no usable cache it returns `unavailable`. Cache read/write failures do not prevent fresh data from being returned. The evolution route caches the upstream chain itself, then projects it through the selected form's manifest identity; family members can share one chain cache while preserving form-specific node labels. Family icons use stored Pokémon ID stems and PNG paths rather than one API request per node; Scarlet/Violet icons are followed by official-artwork PNGs. Image URLs are checked against the PokéAPI sprite repository before being returned; bytes load from GitHub in the browser and are not server-cached. The battle catalog and damage engine do not call this adapter. These behaviors support [REQ-003](requirements/requirements.md#req-003) and [REQ-009](requirements/requirements.md#req-009) without promising that every descriptive image stays reachable when its remote host fails.

Move entries are served by `GET /api/pokedex/:species/moves` from the pinned local Scarlet/Violet snapshot. The endpoint returns source revision/version-group metadata, localized move names, nullable type/category metadata, acquisition methods, learning levels, and machine numbers where available. It reports `no-scarlet-violet-learnset` for entries without recorded base-game data. Egg moves are identified as such; no parent species are inferred. This source is informational and has no effect on team validation.
