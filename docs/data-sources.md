# Data sources and publication policy

**Scope:** Generation 9 battle and Pokédex data and the small curated pro-team collection in the first release. This living document applies the accepted [data authority decision](adr/ADR-002-data-authority-and-provenance.md) to source selection, cache behavior, and publication review. It records what the current code does and what still needs a human release check; it does not assert tournament legality or grant rights to third-party text or images.

## Authority by data type

| Data used by the site | Authority and current implementation | Boundary |
| --- | --- | --- |
| Type effectiveness, species names and base stats, moves, abilities, items, natures, and damage mechanics | Pinned `@smogon/calc` `0.12.0`, selected with `Generations.get(9)` in the [catalog](../apps/api/src/modules/catalog/catalog.ts) and [damage adapter](../apps/api/src/modules/damage/smogon-adapter.ts). The [calculator project](https://github.com/smogon/damage-calc/blob/master/README.md) supplies a generation-specific data layer and damage ranges. | These values are not replaced by PokéAPI fields. Dependency upgrades need catalog and representative damage regression checks. |
| Pokédex ID, sprite URL, height, and weight | The server's [PokéAPI adapter](../apps/api/src/modules/catalog/pokeapi-adapter.ts) requests the [Pokémon endpoint](https://pokeapi.co/docs/v2#pokemon) for a known catalog species and stores the selected response in `PokedexCache`. | Descriptive only. A missing response, form mapping, or sprite must leave battle features available. The cached value contains a sprite **URL**; the image bytes themselves are not cached by this adapter. |
| Pro-team identity, placement, format, and sets | Manually entered [curated records](../apps/api/src/modules/pro-teams/pro-teams.ts), each linked to a named player report and its exact team paste. Official tournament pages can corroborate event and placement or show a public sheet. | One source may not support every field. The entry must say which version it represents when sources conflict. Unpublished EVs or IVs remain unknown. |
| Guest and saved teams | Entered by the user, validated against known names and field ranges. | These are user data, not evidence that a set was legal or played in an event. |

The project credits the calculator and PokéAPI in the UI and links each pro team to its publication and paste. The [Smogon calculator README](https://github.com/smogon/damage-calc/blob/master/README.md#license) identifies the package's MIT license. [PokéAPI's fair-use policy](https://pokeapi.co/docs/v2#fair-use-policy) asks consumers to cache requested resources; the server caches selected response fields, while sprite image bytes remain external. Review that use against the policy before release. The rights to Pokémon imagery and to reproducing article text are separate matters. Do not assume that an open API or a credit line alone grants every reuse right. The site currently links to reports rather than copying their prose.

## PokéAPI mapping, cache, and failure behavior

The API first requires a species known to the pinned Generation 9 catalog. A [small explicit map](../apps/api/src/modules/catalog/pokeapi-adapter.ts) covers Wellspring, Hearthflame, and Cornerstone Ogerpon, Rapid Strike Urshifu, and female Indeedee. A plain name without a hyphen uses the calculator's normalized ID. Unmapped names containing a hyphen return `unavailable` rather than silently substituting another form. That rule is conservative but also catches **hyphenated base species**, not only forms; descriptive coverage for names such as `Chien-Pao` needs an explicit mapping or a better distinction. Do not present the current map as complete form support.

A cached response younger than 24 hours is returned without a network request. Otherwise the adapter requests PokéAPI with a four-second timeout, stores the selected fields, and returns them. On fetch, status, or parse failure it returns an older cached payload if one exists; with no cache it returns `unavailable`. The current response does not label an older payload as stale. The battle catalog and damage engine do not call this adapter. The [test strategy](testing/test-strategy.md) calls for success, timeout, stale-cache, mapped-form, and unmapped-name checks; that outage exercise has not run. This behavior supports [REQ-003](requirements/requirements.md#req-003) and [REQ-009](requirements/requirements.md#req-009) without promising that every descriptive image stays reachable when its remote host fails.

## Rules for a credited pro-team entry

1. Identify the player, event, placement, format/regulation, a consistently defined event date, and an accessible publication with title, publisher/author, publication date, and URL. Prefer an organizer page for event facts and placement when it covers the player; a first-person report can support facts it states directly.
2. Link the **exact** sheet or paste used for the stored sets. Compare all six species and every represented item, ability, Tera type, nature, move, EV, and explicitly stated IV against that source. A report's linked paste is stronger evidence for exact spreads than an official public sheet that omits them.
3. Store only published spread values. An omitted EV or IV is unknown, not an inferred zero, 31, or tournament convention. An explicit `0` remains a known value. Keep publication provenance separate from calculator validation; known names do not establish that the player used a combination.
4. Do not silently merge conflicting sources into a supposedly exact tournament set. Label the entry by the source version it follows, record the conflicting field, and seek owner review before calling it an official public sheet. If material fields cannot be supported or labelled, withhold an exact-set claim.
5. Review the visible page before release: title and placement match the source, links resolve, unknown fields are explained, and the presentation does not imply sponsorship or ownership of the publication. Recheck sources when changing a record. Keep the exact source URLs alongside the curated data so a reader can inspect them.

The current `ProTeam` representation preserves the fields listed in rule 2 but omits source-paste nicknames, gender, and Pokémon level. Its `source` object stores title, report URL, and paste URL, but not publisher/author, publication date, or a source-version note. This is a **selected display model**, not a byte-for-byte copy of a paste. Do not advertise it as a complete exported battle-ready team until the missing fields are handled or the limitation is made clear.

The links below were inspected on 2026-09-27. This is a source comparison, not final human publication approval.

| Record | Sources and supported claims | Issue to resolve before claiming an exact official event sheet |
| --- | --- | --- |
| `worlds-2024-ceribelli` | [Pokémon's 2024 VGC Masters page](https://www.pokemon.com/us/play-pokemon/worlds/2024/vgc-masters) identifies Luca Ceribelli as champion and Regulation G. His [first-person report](https://victoryroad.pro/2024/09/22/luca-ceribelli-worlds-report/) links the [paste used by the code](https://pokepast.es/774751c5dc2c4500), which supports the stored six species and represented set fields. | The official public page lists his Urshifu as **Water Tera with Detect**, whereas the report and linked paste list **Stellar Tera with Protect**. The code follows the **report/paste version**, but the UI does not label that distinction. Add a source-version note or resolve the discrepancy before identifying it as the official public sheet. The report/paste also show Level 50, which the record does not carry. |
| `worlds-2025-brok` | Aaron Brok's [first-person Worlds report](https://victoryroad.pro/2025/10/31/aaron-brok-worlds/) states 13th place and links the [paste used by the code](https://pokepast.es/e7a476940e468a9d). The represented species and set fields agree with that paste. [Pokémon's 2025 event page](https://worlds.2025.pokemon.com/en-us/) gives the event window as August 15–17. | The paste contains nicknames and a Level 83 Cornerstone Ogerpon, while the curated model omits nickname and level. That omission should be visible if the UI later offers team export or battle use. |

The `eventDate` field currently stores **2024-08-18** for the first record and **2025-08-15** for the second: the last and first day of their respective event windows. Its meaning is therefore inconsistent. Define whether it means event start, final day, or another milestone, then normalize the records and UI label. Until then, read it as an unqualified date, not a verified one-day event date. The publication dates of the reports are separate from the event dates.

## Release review and source traceability

Before publishing or updating a pro team, the owner should compare the rendered record with its linked publication and paste, check any organizer source for the event facts it actually provides, and record unresolved conflicts. The [requirements](requirements/requirements.md#req-008) and [test strategy](testing/test-strategy.md) keep the acceptance check and verification gap. The code has no automated source-import pipeline, so a source change cannot silently rewrite the collection.

The validated course document **Fundamentos del desarrollo de software (Módulo 0) → Buenas prácticas → Ética en el desarrollo** informs the care taken with attribution and reuse rights. It does not select Smogon, PokéAPI, the two player reports, or a legal permission for their assets. Those source choices come from the owner's approved plan and the linked project/external evidence above; unresolved source conflicts remain visible rather than being reconciled by assumption.
