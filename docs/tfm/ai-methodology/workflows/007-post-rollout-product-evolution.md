## Planned implementation and current progress

The owner approved the following sequence on 2026-10-22:

1. Establish the shared English/Spanish documentation policy and record this workflow in both languages.
2. Generate official English and Spain Spanish Pokémon labels and descriptions from pinned sources; extend shared contracts.
3. Add reactive locale selection, complete translations, and checks for untranslated UI literals.
4. Order the Pokédex by national number and load the full browseable list progressively.
5. Add Scarlet/Violet move acquisition data and a searchable moves panel.
6. Add direct routes and basic SEO for Pokémon entries.
7. Translate the root README and all non-prompt Markdown files under `docs/`.

Parts 1–3 are implemented. Part 1 established the shared bilingual documentation rule and this paired record. Part 2 added a reproducible generator pinned to PokéAPI revision `2bf639e5572812a67d2b94903fdcb9d095f5aeb2`, using language 7 for Spain Spanish and excluding language 14 (`es-419`). Its generated snapshots contain 1,324 official species/form labels, localized move, ability, item, type, and nature catalogs, National Pokédex numbers, collision-checked slugs, and base-form flags. The generator records official naming overrides and explicit exceptions for simulator-only or custom entries. It also records 267 bilingual official ability flavor-text pairs and 50 abilities whose official bilingual resource or flavor text is unavailable, rather than inventing descriptions.

Shared contracts now carry localized catalog maps while preserving canonical battle names, National Pokédex metadata, bilingual ability descriptions with source version groups, structured evolution-condition alternatives, and unavailable-reason codes. The API returns those generated ability descriptions from the local snapshot; it no longer makes a separate live request per ability.

Part 3 adds a reactive English/es-ES locale provider. A saved choice takes precedence over the browser locale; Spanish browser locales resolve to Spain Spanish, unsupported locales fall back to English, and storage failures do not prevent use. The round flag switch sits beside the theme control. Notices and errors retain message identifiers and values, so they update immediately when the language changes without resetting active UI state. Screen copy, accessibility labels, evolution conditions, Pokémon descriptions, and calculator details are localized. The calculator now shows structured matchup inputs and calculated damage details instead of the engine's English narrative. Spanish Pokémon labels and ability flavor text use the generated es-ES catalog; source-backed overrides supply the confirmed Spanish names for seven evolution locations absent from the pinned location-name CSV.

An AST-based UI-copy check rejects static visible JSX strings outside the locale dictionaries. Tests check dictionary keys and placeholders, locale resolution/storage behavior, live switching while retaining drafts and selection, translated evolution requirements, and all six primary screens with a pseudolocale. The production web build and both API/contracts builds pass. The focused browser E2E spec could not start because this environment lacks Playwright's Chromium headless executable; desktop/mobile visual review remains pending.

Part 4 sorts eligible entries by National Pokédex number, puts a base form before alternate forms sharing that number, and uses the canonical name as a deterministic tie-breaker. The UI displays a padded national number alongside each entry. It renders 60 matches first, appends another page on list-scroll bottom, and also exposes an accessible load-more button. Search filters the complete catalog before the visible limit, matches both canonical and active-language names, and ignores accents. Changing the query resets the visible page; the full browseable list remains available.

Part 5 adds reproducible Scarlet/Violet learnsets using the same pinned PokéAPI revision. The generator reads `pokemon_moves.csv`, acquisition-method data, and `machines.csv`, and writes a compact 1,165,103-byte server-side snapshot for 870 eligible species/forms; 454 entries, including Abra, carry an explicit unavailable state. It selects only version group 25 (`scarlet-violet`) and excludes version groups 26 and 27 (`the-teal-mask` and `the-indigo-disk`) so the base-game learnset is not mixed with DLC. Official Spanish move labels use the existing es-ES catalog, with PokéAPI language 7 move names filling any missing catalog labels; validation confirms all 679 move definitions in the learnsets have Spanish labels. Machine moves include their Scarlet/Violet TM numbers when the pinned dataset provides them. The snapshot records source revision and game group, and generation/startup require no runtime dataset download. See the [PokéAPI move/version-group documentation](https://pokeapi.co/docs/v2#pokemon-moves) and [machine documentation](https://pokeapi.co/docs/v2#machines).

The shared contract and `GET /api/pokedex/:species/moves` endpoint return one entry's moves, type, physical/special/status category, acquisition methods, applicable learning levels, and available TM numbers. Level-zero acquisition is represented as an event without “Level 0”; machine, egg, tutor and form-change methods omit levels. The panel appears below evolution. Scarlet/Violet is a folder-style generation tab, with nested Level, TM, and Egg method tabs; an Other tab appears only when the entry has uncommon tutor, form-change, or other acquisition data. This keeps each move list compact while retaining every returned method. Type and battle category use compact icons with accessible localized names rather than repeated visible labels. PokéAPI supplies damage-class metadata but no category artwork, so the category column uses official Scarlet/Violet game icon assets served by Bulbagarden Archives: [physical](https://archives.bulbagarden.net/wiki/File:PhysicalIC_SV.png), [special](https://archives.bulbagarden.net/wiki/File:SpecialIC_SV.png), and [status](https://archives.bulbagarden.net/wiki/File:StatusIC_SV.png). The API's Helmet `img-src` policy explicitly allows the archive origin. Derived egg-parent candidates were removed after review because the available data did not establish reliable parent information; the API and UI report only egg-move acquisition. The moves heading is simply “Moves”/“Movimientos”. Search covers canonical English and active Spanish names, selects the method tab containing a matching move, and distinguishes no text match from a known move absent in that learnset. Entries without base Scarlet/Violet data receive a separate unavailable message. Requests are aborted when the selected entry changes.

Part 6 adds React Router paths for the main pages and each eligible Pokédex entry. URLs resolve through the collision-checked generated slug manifest, including exceptional names such as `mr-mime`, `nidoran-f`, `farfetchd`, and `charizard-mega-x`. The URL is the source of truth for the selected entry; navigation uses links, so direct opening, refresh, copied URLs, and browser history retain the selected entry. Shared application state remains mounted while route content changes. Evolution-family and overview links navigate to their corresponding routes.

The app updates document language, localized page title and description, robots metadata, and absolute canonical link on route and language changes. The canonical origin comes from the API's public site configuration. Production serves an allowlisted `robots.txt` and a sitemap containing public page paths and eligible entry slugs; development and staging disallow indexing. Fastify's SPA fallback serves the app shell for valid page and entry routes and returns HTTP 404 for unknown Pokédex slugs. This is client-rendered SEO metadata: it improves direct navigation and provides basic discovery signals, but does not guarantee indexing or rankings. Server rendering and separate language URLs remain deferred, consistent with [Google's JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Part 7 is implemented. The root README and all 25 non-prompt Markdown source documents under `docs/` have Spanish counterparts; the operational secrets README is paired as well. English and Spanish documents begin with reciprocal language badges. The dated audits retain their original as-of dates and findings, while living guides were updated for the current localization, Pokédex routes, moves data, deployment behavior, and validation evidence. Archived prompts and agent instructions remain in English. `pnpm docs:check` runs the repository's dependency-free documentation checker; it checks all 27 public language pairs and local Markdown paths/fragments while excluding the prompt archive. A direct `node scripts/check-docs.mjs` run passed for 54 Markdown files. Human review of the Spanish wording, translated official terminology, and rendered layout remains pending.
